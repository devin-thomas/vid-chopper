VidChopper 1.0.0 is the first stable release. It puts the Windows desktop app and command-line tool on one shared Qt-free probe, planning, export, progress, verification, and manifest engine.

## Highlights

- Keeps the existing Qt desktop workflow while removing UI-thread waits during GPU and ffmpeg detection.
- Uses the same process, probe, planning, and export behavior in `VidChopper.exe` and `VidChopperCLI.exe`.
- Preserves JSON/YAML ChapterFiles, embedded chapters, dry-run planning, deterministic output naming, and JSON/CSV manifests.
- Bounds in-memory desktop logs and keeps curated and advanced output responsive during long exports.
- Includes the first-party VidChopper CLI agent skill and its integrity manifest for offline use.
- Verifies the portable archive on a clean Windows runner before publication.

## Supported Boundary

VidChopper 1.0.0 supports Windows 10 and Windows 11 on x64. The release archive contains the GUI, CLI, Qt runtime, Microsoft Visual C++ runtime, `yaml-cpp.dll`, license, notices, and the offline CLI skill.

`ffmpeg` and `ffprobe` are required but intentionally not bundled. The clean release evidence uses FFmpeg 7.1.1. Install the tools separately and keep them on `PATH`, or configure their locations in the desktop Advanced Settings.

## Known Limitations

- Exports run sequentially.
- The desktop chapter editor displays frame timestamps using the probed rate rounded to a whole-number display FPS.
- Embedded metadata import is intentionally conservative.
- The CLI normally uses overwrite mode and has no dedicated safe-overwrite flag; use dry-run output inspection and a fresh destination when files already exist.
- macOS, Linux, self-patching, and automatic update checks are not part of the 1.0.0 support promise.

## Deferred Work

Manual and opt-in update checks (VID-10) and broader test-architecture expansion (VID-43) were explicitly canceled as 1.0.0 requirements. They are not hidden release gates. Broader presentation polish for `vidchopper.app/docs` is also post-1.0 work.
