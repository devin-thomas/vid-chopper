# 1.2.0 Release Evidence

This record documents the completed promotion gate for the cumulative Windows and Apple Silicon macOS release published on 2026-09-04.

## Required candidate identity

- One source commit for the Windows ZIP, macOS DMG, and standalone macOS CLI archive.
- A passed `macOS Candidate` workflow run for the DMG and CLI archive.
- A passed `Release` workflow run in `qualify` mode that requalifies Windows and aggregates all six candidate/checksum assets.
- Positive sizes and SHA-256 hashes for all six assets in `packaging/releases/1.2.0.json` before promotion.
- A `packaging/releases/1.2.0-macos-physical-evidence.json` record whose source commit, candidate run, and hashes match the cumulative candidate evidence.

Copy `packaging/releases/macos-physical-evidence.example.json` to that versioned filename only after a
tester is ready to replace every placeholder with observed evidence. A pending or partially passed file
cannot authorize publication.

The successful cumulative qualification artifact includes a populated `release-ready-manifest.json` and
a `macos-physical-evidence.pending.json` seeded with the exact source, run ID, filenames, and hashes. Use
those generated records to avoid retyping candidate identity; replace only observed physical fields and
outcomes, and review the final diff before committing it.

## Physical macOS gate

The physical evidence must contain one passed record for role `m4-pro`. Every journey is required on that machine: checksums, application install and relaunch, source probing, embedded/default chapters, chapter editing, x264 and VideoToolbox exports, cancellation with no orphaned FFmpeg process, manifest verification, output-folder opening, native settings persistence, explicit/portable config failure, CLI archive execution, no-sudo installer, installed command in a fresh shell, dry run, and real export.

The M4 Pro must use browser-downloaded bytes and record quarantine, per-app approval, and successful relaunch without changing global Gatekeeper settings. Ad-hoc signing is the only signing claim; the release is not Developer ID signed or notarized.

For 1.2.0 only, the release owner may explicitly waive the unfinished VideoToolbox completion and cancellation/no-orphans journeys when the evidence record names both tests, the authorizer, timestamp, and reason. A waiver must use `waived-by-release-owner`; it must never be recorded as a passing test. Every other M4 Pro journey remains mandatory.

## Promotion

The protected `release-environment` job downloads the retained cumulative candidate run instead of rebuilding. It rejects missing or failed physical evidence, checks every local file against both the release manifest and cumulative automated evidence, publishes all six unchanged files, downloads every remote asset, and compares each remote byte stream with its qualified candidate.

Publication workflow [33870435599](https://github.com/devin-thomas/vid-chopper/actions/runs/33870435599) published `v1.2.0` at `2026-09-04T11:59:40Z` from merge commit `07342993fb78c2af8f63a65c6961aa25e3dd52fe`. The workflow and an independent local download verified all six remote asset sizes and SHA-256 hashes against `packaging/releases/1.2.0.json`.
