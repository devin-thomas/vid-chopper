# 1.1.0 Foundation Evidence

This is the documentation contract for the `1.1.0` candidate record. It is intentionally not a release
approval and does not invent a Windows candidate hash. VCU-111 owns the package, release-workflow, and
version-metadata changes that fill the candidate fields below.

## Boundary

- Product version: `1.1.0`.
- Published asset class: Windows 10/11 x64 portable binary package only.
- macOS and Linux: source/CI core and CLI qualification plus GUI compile/launch smoke evidence only;
  no end-user support and no public Unix package.
- Candidate rule: build the Windows candidate once, test those exact bytes, and publish only the passed
  candidate whose SHA-256 is recorded here.

| Adjacent checksum name | `Pending VCU-111 candidate` |

The values above are required evidence fields, not placeholders that authorize publication. A missing,
changed, or mismatched value blocks the release.

## Dependency record

Record the exact versions and paths used by the candidate and every assigned lane:

| Dependency or tool | Required record |
| --- | --- |
| CMake | Version, generator, and compiler toolchain |
| C++ compiler | Name and version |
| vcpkg | Repository commit matching `vcpkg.json` `builtin-baseline` |
| Qt | Pinned Qt 6 minor and architecture; the 1.0 baseline is Qt 6.9.0 |
| FFmpeg | Exact path and version; supported range is 6.1 through major 8.x |
| ffprobe | Exact path and version; supported range is 6.1 through major 8.x |

FFmpeg and ffprobe remain external. A missing executable, unsupported version, or pair mismatch must be
reported with the selected paths, versions, and direct remediation; the application must not silently
install or download either tool.

For each lane, record the OS/version/architecture, machine or runner, source commit, dependency versions,
test commands, outcome, tester/timestamp, and failure or retest notes. Any assigned failure blocks
publication.

## Config, tools, and encoder evidence

The evidence must show the documented foundation semantics:

- Windows keeps its existing adjacent settings behavior; macOS uses
  `~/Library/Application Support/VidChopper/`; Linux uses `$XDG_CONFIG_HOME/VidChopper/` or
  `~/.config/VidChopper/`.
- GUI and CLI settings remain separate as `VidChopper.ini` and `VidChopperCLI.ini`. CLI reads the GUI
  file only when `--use-gui-config` is passed, and precedence remains defaults, optional GUI import, CLI
  settings, ChapterFile values, then explicit supported CLI flags.
- The current CLI flags are `--embedded`, `--dry-run`, `--crf`, `--cq`, `--preset`, `--threads`,
  `--aggregate-json`, `--aggregate-csv`, `--stop-on-first-error`, `--use-gui-config`, `--version`, and
  `--help`/`-h`. Do not add a final `--config`, `--portable`, `--ffmpeg`, or `--ffprobe` flag to evidence.
- Auto encoder selection uses a real capability test and falls back to x264 before export when hardware
  capability fails. Explicit hardware failure blocks export and does not change the stored preference.
  VideoToolbox is deferred to `1.2.0`.

See [CLI settings](cli-settings.md), [ChapterFile schema](cli-config-schema.md), and the
[support matrix](support-matrix.md) for the human-readable contract.

## Publication gate

VCU-111 must retrieve the exact passed Windows candidate, verify its SHA-256 against this record, publish
that unchanged asset and adjacent checksum, download the public asset, and verify the remote SHA-256
again. Unix build artifacts may remain internal evidence but must not be attached as `1.1.0` release
assets.

This file does not modify `.github/workflows/release.yml`, `CMakeLists.txt`, `vcpkg.json`, release
metadata, or generated package artifacts. Those ownership boundaries are deliberate.
