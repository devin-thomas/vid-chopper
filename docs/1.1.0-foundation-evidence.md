## Config, tools, and encoder evidence

The evidence must show the documented foundation semantics:

- Windows keeps its existing adjacent settings behavior; macOS uses
  `~/Library/Application Support/VidChopper/`; Linux uses `$XDG_CONFIG_HOME/VidChopper/` or
  `~/.config/VidChopper/`.
- GUI and CLI settings remain separate as `VidChopper.ini` and `VidChopperCLI.ini`. CLI reads the GUI
  file only when `--use-gui-config` is passed, and precedence remains defaults, optional GUI import, CLI
  settings, ChapterFile values, then explicit supported CLI flags.
- The current CLI flags are `--embedded`, `--dry-run`, `--config`, `--config-path`, `--portable`,
  `--crf`, `--cq`, `--preset`, `--threads`, `--aggregate-json`, `--aggregate-csv`,
  `--stop-on-first-error`, `--use-gui-config`, `--version`, and `--help`/`-h`. Explicit config paths
  and portable mode are mutually exclusive; there are no `--ffmpeg` or `--ffprobe` flags.
- Auto encoder selection uses a real capability test and falls back to x264 before export when hardware
  capability fails. Explicit hardware failure blocks export and does not change the stored preference.
  VideoToolbox is deferred to `1.2.0`.

See [CLI settings](cli-settings.md), [ChapterFile schema](cli-config-schema.md), and the
[support matrix](support-matrix.md) for the human-readable contract.
